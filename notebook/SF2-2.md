### 2026-10-08T15:15-07:00 — decision: what counts as a reference, a citation and a record

Within the design's text, chosen here and listed for the orchestrator to confirm:

- **Records** are facts, instance rows and variant rows, in one id namespace per spec id per
  root (the verification record keys all three).
- **The gate's reach** follows every fact reference a record makes (premises, `relates`, an
  emulated entry's `observation`), and every anchor in its support, its premises' support and
  its conflicts' support. The design lists "facts, premises, instances and variants"; a conflict
  entry's anchor cites the same code, so it is gated too. A notice's repos entry is gated like an
  anchor, since the notice copies that file's text.
- **One gate function** (`Checker.gate`, over board-expert's `spdx.py`) serves the direct check
  (anchors and notices against their own file's root), the transitive one (each reference's reach
  against the citing root) and `--require-license`.
- **Layer order** compares layers only, not pointer order inside a layer; an overlay must sit in
  a layer no earlier than its target's.
- **Second spellings refused:** an `accepts` entry not in its canonical SPDX spelling (`GPL-2.0`
  for `GPL-2.0-only`); a premise list naming one fact twice in any spelling (`#a`, `spec#a`,
  `spec@root#a`); a page number with leading zeros; one root given twice or nested in another;
  a file whose name says spec but would not be discovered (`.spec.yml`, `.SPEC.YAML`), a format 1
  `.spec.md`, a facts file, a nested marker.

### 2026-10-08T15:15-07:00 — surprise: loading `spdx.py` by path needs `sys.modules`

`importlib` loads a module from a file without registering it; `spdx.py`'s frozen dataclasses
look their module up in `sys.modules` while the class is built, and the first smoke run was an
internal error (exit 100). The loader now registers the module before executing it.

### 2026-10-08T16:02-07:00 — direction: round-1 findings and the orchestrator's decisions

Round 1 (Codex `ro` and an executing Claude reviewer; artifacts under `review/` in the run).
Both found the transitive gate failing open, in two ways, and Codex found a third gap:

- an unresolvable hop in a chain through a context root was only a context warning, so a docs
  root could rest on GPL source and exit 0;
- an ambiguous resolution (twin root names, a fact id declared twice) was gated on whichever
  candidate came first;
- a directory `os.walk` could not list was skipped silently.

Orchestrator principle: **the gate fails closed**. Anything it cannot establish is an error on
the checked citing file. The seven interpretations in the 15:15 entry were accepted as
recommended. Further decisions:

- the marker's `license` is required;
- placeholders are template-shaped;
- extension fragments may not declare citation fields;
- `parts` and `instances[].ip` into another root are composition, not a fact resting on a
  source, and stay ungated (the design's scope).

### 2026-10-08T16:02-07:00 — attempt: fail-closed resolution

`resolve` now answers "a record", or "nothing", "ambiguous", or "cannot be resolved". The last
covers two cases: the root was not read in full (invalid marker, unlistable directory), or a
file there failed to load or validate and may declare the spec (any spec, when it did not
parse). `reach` returns the unestablished hops, and each becomes an error on the citing file.
A side effect: an unparseable file blocks every qualified reference into its root. Two of
`bad_root`'s files were unparseable and masked another fixture's defect, so they moved to a
`bad_load_root` of their own, which also shows the blocking.

### 2026-10-08T16:52-07:00 — direction: round 2 hit the stop rule; the user chose one root-level rule

Round 2 (artifacts `review/codex2`, `review/claude2`) confirmed round 1's fixes. Both reviewers
then found more fail-open paths of the same kind: a defect in a context root changed what a
checked reference resolved to, while the defect itself was only a context warning. Their inputs:

- a misnamed spec file (`.spec.yml`, a case variant);
- a schema-failed file whose `id` or `overlays` misled the per-file narrowing;
- a second root with the same name whose marker could not be read;
- a repos name listed twice (Codex and Claude);
- an extension fragment admitting `repo` and `path` through `patternProperties` (Codex).

That met the stop rule: a same-kind blocker in the same layer.

**User decision ("distrust broken roots"):** a root with any error of its own is untrusted, and
no reference may rest on it. While any marker is unreadable, every root-qualified reference
fails. Extension fragments use plain `properties` and value constraints at every depth.

### 2026-10-08T16:52-07:00 — attempt: the trust rule replaces the per-path patches

- **Untrusted roots:** every error-severity finding is recorded on its root before context
  downgrading. Resolution refuses an untrusted root other than the citing file's own, and
  refuses every root-qualified reference while a marker is unreadable.
- **Propagation:** a final pass, repeated until nothing changes, fails each reference whose
  reach rests on an untrusted root. Each such error makes the citing root untrusted in turn.
  A reference already reported as failing is not reported twice.
- **Removed:** the per-file `failed`-id narrowing and the `incomplete` list.
- **Misnamed files:** any file named with `.spec.` or `.facts.` that is not `*.spec.yaml` is an
  error; this now covers backups.
- **Fixtures:** `references/untrusted/` holds all 19 round-2 inputs, each failing on the checked
  file alone, and one warning-only root that stays trusted.
- **Superseded:** one SF2-1 test that exercised `anyOf` inside a fragment now asserts that the
  fragment is refused.
