# SF2-11 — The three spec repositories cut over and published

**Terms:** a root declares a spec repository's license policy; a context repository is one whose
roots another repository's checks read. See the [glossary](../GLOSSARY.md).

Plan: [SF2-11](../docs/SPEC-FORMAT-V2-PLAN.md#sf2-11--the-three-spec-repositories-cut-over-and-published).
Run: `sf2-11-20261009-01`. This chapter records discoveries and dead ends; the outcome is in
[the evidence](../evidence/SF2-11.md).

### 2026-10-09 — preparation

The unit was split: prepare the cutover branches, draft pull requests and scratch gate pull
requests overnight, and leave merging and enabling Pages for the user's go.

The template assumes the root marker at the repository top. Here the repository is checked out
beside its context repositories, so `publish.yml` takes the root from a subdirectory and the
context repositories as sibling checkouts.

Context repositories are read at `main` rather than pinned: a pin would name a commit that does
not exist until the upstream merges.

Downstream pull request CI cannot go green before the upstream merges, because it reads the
upstream's `main`. The plan's merge order implies this; it was expected, and it is why each
downstream run was repeated after the upstream merge.

The upstream-stale criterion needs a reference across roots whose CI reads the upstream `main`,
so it could not be proven in published CI before docs merged. It was proven locally first and
deferred.

The gpl checks workflow checked out the permissive context under a path the repository did not
ignore; the fix round added it.

### 2026-10-09 — scratch gate pull requests

The fit change passed and the misfit change failed with the license named in the error, both in
published CI. Both were closed unmerged and their branches deleted.

### 2026-10-09 — reviews

Both reviewers found no blocker. The finding common to all three repositories was a deploy job
that would run on forks, where no Pages site exists.

Dead end: the Opus review's S1 was text claiming context errors are only warnings. The code was
right and the sentence wrong, so the text changed and no code did.

### 2026-10-10 — merging

Pages has to be enabled (source: GitHub Actions) before each merge. The deploy job runs on every
push to `main`, and without a Pages site it would fail the Publish run; this was inferred from the
action, and the order (enable, then merge) avoided it, so the failure was not observed.

Each downstream pull request was re-run after the upstream merge and went green; with no branch
protection, the discipline is the only gate.

### 2026-10-10 — upstream-stale in published CI

The proof needed a docs branch that edits a fact and a permissive branch that cites it. Editing
the docs fact also made the docs fact stale against its own verdict, so the demonstration shows
the cross-repository check firing alongside an own-stale fact. The pull-request run failed and the
`workflow_dispatch` run warned with the same line. Both scratch pull requests and branches were
removed.
