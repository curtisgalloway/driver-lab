How this works

A spec is a set of short, cited claims about a piece of hardware: where the debug console is, how the boot ROM picks a boot device, which address and interrupt a block uses. An agent writing a driver reads the spec instead of digging through vendor source.

  1. Specs are YAML, one per part. A board spec names its parts (an SoC, companion chips). Peripheral specs cover how to program one block, and IP specs describe a block design used in several chips. Each fact is one claim with a support list naming its evidence: a document page, device-tree or source lines at a pinned commit, a standard, or a labeled inference.
  2. Roots and licenses. Specs live in roots, each with its own license. A root built only from public documents can be used by anyone; a root that cites GPL source is GPL like that source. An overlay in one root adds facts to a spec in another. This page combines the roots listed below, and the root tag on each fact says where it came from.
  3. Every fact is verified separately. A verifier agent reads each fact in a fresh context, opens the cited evidence and records a verdict in a separate .verify.yaml file. PASS means the evidence supports the claim. GAP means no source read so far states it, and it names the check that would settle it. FAIL means the evidence disagrees with the claim, and an author has to fix it. A verdict goes stale when the fact or its evidence changes afterward.
  4. Facts link across specs. A board fact can refine a SoC fact, qualify it with a condition, or say the same thing from another source. These links are the lines in the Graph view.
  5. The main test is a rebuilt driver. A driver written from a spec alone is run side by side with the original driver against the same device, and their behavior is compared. Verification shows that the citations hold. The rebuilt driver shows whether the spec is complete enough to use.

The views

Outline
The spec → its parts, peripherals and IP blocks → sections → facts. Opening a fact loads it in the sidebar.
Graph
One node per spec, sized by fact count, ringed by verification state. Dark lines show which spec contains which. Colored curves are fact links, wider for more links. Click a node to list its facts.
Memory map
Instances that have a recorded base address, with interrupts, clocks and the facts that cite each address.
Coverage
One square per fact, by spec and section. Hover a legend item for its meaning.
Open items
Failures, gaps, stale verdicts, outstanding bench and reading checks, and what this page cannot show.
