# L02s: spec revision 5 (PSCON bit 11)

## Terms

- **Spec** — the clean-room implementation spec for the Intel 82540EM (e1000) core network
  path ([L02b](L02b.md), [L02c](L02c.md)). **Revision 4** is the one the candidate was written
  from ([L02e](L02e.md)).
- **PSCON** — the 82540EM PHY's register 16, PHY Specific Control (manual Table 13-31). Its bit
  11, "Assert CRS on Transmit", decides whether the PHY raises **carrier sense** (the "wire is
  busy" signal the MAC watches) while it transmits.
- **Half / full duplex** — a link that carries one direction at a time and detects collisions /
  one that carries both at once. Bit 11 "has no effect in full duplex".
- **TNCRS** — the controller's "transmit with no carrier sense" statistics counter (§13.7.12).
- **Verifier** and **verification record** — as in `spec-verifier`: a fresh agent that checks
  each claim against the source it cites and writes its verdicts to a file outside the spec.
- **Operator** — the agent session that edited the spec and wrote this record.

See the [glossary](../GLOSSARY.md), the [plan](../IMPLEMENTATION-PLAN.md) (L02s), and the
[notebook chapter](../notebook/L02s.md).

The five changes (`diff` of the two files, 5 hunks):

1. **Header:** revision 5, dated, naming the bit-11 change in G4 and §9.2.
2. **§5.4 G4:** PSCON is now a read-modify-write that also sets bit 11. The step gives the
   bit's documented values (reset 0b "Never assert on transmit", 1b "Assert on transmit", no
   effect in full duplex) and argues for setting it as an `[inference]` with stated premises:
   §8.4.2 expects carrier sense within one slot time of a half-duplex transmission and calls a
   PHY that fails this possibly "configured incorrectly"; bit 11 is the only PSCON field about
   carrier sense on transmit; it is assumed (not stated by the manual) that this is the carrier
   sense the MAC watches; and the bit cannot affect a full-duplex link. Contrary text is
   recorded (§8.4.2: a transmission "completes successfully even if internal carrier sense is
   not asserted"; the reset default is 0b). Confidence medium. Verification method: on
   hardware, read TNCRS over a 10/100 half-duplex link with the bit clear and set, as
   informative only, because the manual contradicts itself on whether TNCRS counts in half
   duplex (§8.4.2 against §13.7.12).
3. **§5.4 ordering note:** G4 must precede the auto-negotiation restart (G7) for bits 6:5 **and
   11**, which take effect only at a PHY soft reset, an auto-negotiation restart, a power-down
   exit or a link loss (§11.1.3).
4. **§5.4 `[source-observed]` PHY extras:** revision 4 told implementers to set the bit only
   "if half-duplex links misbehave"; the guidance now points at G4, and the bullet notes that
   the manual requires the before-G7 order for this bit.
5. **§9.2 PSCON row:** bits 6:5 = 11, bit 1 = 0, bit 11 = 1, read-modify-write before starting
   auto-negotiation, with the same citations.

The candidate needs no change: its L02e repair already sets the bit.

Revision 3's recall result (63 of 66 blind-list rows covered, 3 partial;
[RECALL-r3.md](../evals/e1000/RECALL-r3.md)) stays as measured on revision 3. Recall was not
re-measured on revision 4 or 5. The blind list has no row for PSCON bit 11: a search of
[`requirements.yaml`](../evals/e1000/requirements.yaml) for "PSCON", "CRS", "carrier" and
"register 16" finds nothing.

## Limits

- Only the changed claims and the bit-11 claims were verified; the rest of revision 5 is
  revision 4's text and carries its L02c verification, which had one reading of revision 4's
  own changes.
- Both verifiers and the operator share a model family, and none checked the rendered PDF: the
  quotations and page numbers were checked in the pinned text rendering of the manual. No
  quoted value here depends on a symbol that rendering loses.
- The change is backed by the manual, not by a measurement: nothing in this unit ran, and the
  spec's verification method needs a half-duplex link on hardware.
- The operator edited the spec itself rather than handing the edit to a separate clean editor
  as L02c did; it read no driver or QEMU source in this unit, so the edit stays on the clean
  side, but that rests on the operator's account and the ledger.
- Subagent transcripts are recorded by path in the run's ledger; those paths are temporary.
