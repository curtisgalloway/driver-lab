# SF2-5 — The viewer and publishing

**Terms:** the viewer is the generated HTML reading copy; a badge is generated from structured
fields; a mutation check removes a guard to test whether an assertion catches it. See the
[glossary](../GLOSSARY.md). Plan: [SF2-5](../docs/SPEC-FORMAT-V2-PLAN.md#sf2-5--the-viewer-and-publishing).
Run: `sf2-5-20261009-01` in the private run store. This chapter records implementation discoveries;
the orchestrator records acceptance and review in the milestone evidence file.

## 2026-10-09T19:19:34-07:00 — Parsing and publishing boundaries

- A deep copy of the entire CommonMark parser failed because it retains Python modules. A
  shallow parser copy with a deep copy of its options preserves the shared checked rules and
  disables HTML for the viewer without changing the checker's HTML detection. Copying options
  into an ordinary dictionary also failed: the pinned parser expects attribute access.
- Images inside links and recursively formatted image labels can produce nested anchors. The
  viewer keeps the enclosing destination and renders image-label links as text, avoiding invalid
  HTML while retaining the image-as-link rule for standalone images.
- A page list inside an artifact cannot prove completeness: it can be edited along with missing
  pages. The publishing helper regenerates the inventory and compares every expected view with
  the checked sources before upload and again in the deploy job.
- The existing SF2-4 CLI rejection test deliberately included HTML as an unavailable format. It
  now uses PDF as the unsupported format; new tests cover HTML's success and failure results.
- The workflow remains a template. Its tool commit starts as a refused zero placeholder, and
  context checkouts must be added in both jobs when installing it in dependent spec repositories.
  Real Pages activation belongs to SF2-11.
