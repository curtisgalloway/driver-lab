# L02d3 — check qualification

Unit of the [plan](../IMPLEMENTATION-PLAN.md) (L02d); verdict record:
[evidence/L02d3.md](../evidence/L02d3.md). Terms: a **claim** is a check whose PASS L02f will
cite as evidence about the candidate; a claim is **qualified** when a planted defect that
violates it made that check fail, for that reason, with the valid control passing on the same
harness. See the [glossary](../GLOSSARY.md).

## 2026-09-25T14:23-07:00 — opening
Goal: freeze the claim set, then plant a defect per claim and record claim → defect → run ID,
or `unqualified` / `unobservable` / `insensitive` with the reason. Start: branch
`driver-porting/l02d3` from `origin/main` at `2ea7724`, in its own worktree; no local changes.
Private run store for this unit: a new directory beside L02d2's, same layout.
Approach: qualification runs each target scenario alone on fresh guests, so leftover frames
from an earlier scenario cannot reach it (the L02d2 contamination). No harness change is
planned unless a claim needs one.

## 2026-09-25T14:40-07:00 — decision: the claim set
24 claims (Q01–Q24) frozen in the evidence file, grouped by what the driver must do rather than
one per check name; stimulus checks (floods running, rings wrapped, harness writes, leftover
frames) are preconditions, not claims. The `itr` read-back is not a claim (C4). Committed before
any defect run.

## 2026-09-25T14:40-07:00 — surprise: the reference pads in software
The "pad bit cleared" defect proposed in L02d2 would be equivalent on its own: the reference
calls `eth_skb_pad` on every transmit before the device sees it, and its reset path also sets
TCTL.PSP. The padding defect must clear PSP in both places and drop the software pad.

## 2026-09-25T14:28-07:00 — attempt: 14 defects built, first round launched
Fourteen planted defects d01–d14, one per claim or pair of claims, built out of tree against
the same kernel build with no warnings (d11 needed its removed call kept behind `if (0)` to
build under `-Werror`). Round q1: 29 isolated runs on the L02d2 final harness (identical to
this branch's copy), 8 at a time: the reference alone in each of the ten scenarios as the
control, each defect in the scenarios its claims name, and L02d2's m5 alone in ring-wrap and
rx-overrun to take its detections out of the contamination.

## 2026-09-25T14:35-07:00 — attempt: round q1 results
All ten reference controls PASS. Sixteen of nineteen defect runs FAIL, each on its claim's own
check (details in the evidence table). Three passed: d11 (no reset wait) as predicted, with
gaps down from about 5,970 µs to 13 µs, still over the 1 µs bound: Q18 is insensitive. d09
passed both scenarios.

## 2026-09-25T14:35-07:00 — dead end: d09, ring indices not reset in the clean routine
Equivalent under these scenarios: `ip link set down/up` goes through close and open, and
setting up the ring's resources on open zeroes the indices again. d15 removes both resets and
fails stop-start and down-during-traffic.

## 2026-09-25T14:35-07:00 — surprise: d16's corruption never ran
Flipping a byte only in frames the device marked TCP-checksum-good changed nothing, which
suggests QEMU's e1000 never sets that status here. d16b corrupts every large received frame:
the peer-to-DUT transfer stalls (TCP drops the bad segments) while 3,000 pings pass. So the
MD5 check can only see corruption as a stall on this model; recorded under Q09.

## 2026-09-25T14:35-07:00 — decision: isolated runs are the qualified configuration
No drain step added to the harness. Qualification ran one scenario per boot, 0 leftover frames
in every bring-up; L02f cites a claim as qualified only from an isolated run of its scenario.

## 2026-09-25T14:43-07:00 — attempt: Codex review of the raw runs
Fresh read-only Codex session through `consult`. It confirmed the controls, identities and
failures, and found four medium problems in the record (Q01 claimed pings that never ran;
Q18 mislabeled insensitive though 13 µs meets the rule; the claim set missed 60/61-byte
receive and first load; d16's equivalence overstated) and three low. All fixed; Q25 and Q26
added. Its second turn caught a false reason I had written for Q25 (peer ARP frames reach the
DUT at 42 bytes, not 60), fixed; third turn confirmed the final text.
