# SF2-6: resolve, show and drift

**Terms:**

- *anchor*: the part of a fact's citation that locates source text: a file path with a line
  range, a symbol, a device-tree node or an RTL name.
- *pin*: the full commit a cited repository entry is read at.
- *resolve*: fetching the pinned commit and checking every anchor and cited-file license
  against it.
- *drift*: moving a pin to a newer commit, rewriting moved line ranges and marking anchors whose
  text changed as `stale`.
- *verify after rewrite*: drift's gate (D9). It loads the rewritten bytes strictly and requires
  them to equal the original data plus exactly the intended changes.
- *mutation check*: removes one guard to confirm a test notices.

*Pin*, *mutation check* and *data path* (the keys and list positions naming a parsed value) are
also in the [glossary](../GLOSSARY.md); the other terms are defined above.

## What was built

- **`skills/spec-format/scripts/resolve.py`:** shallow, blob-less `https` fetch ported from
  format 1's rules (size limit, time limit, `--` before every revision and object argument, no
  `file:` or `ext::` URL, a `-`-prefixed value never reaches `git`); anchor resolution for
  `src`, `DT` and `rtl` (path, line range, symbol near the range, device-tree node, search
  scope); per-file SPDX comparison against the entry's license (D12, after the kernel's
  `spdxcheck.py` rules: the first tag in the first five lines); document hashes with
  `--docs-dir`; local `--repo NAME=CHECKOUT`, which reads the declared commit and ignores
  worktree edits and local object replacements.
- **`spec.py show`:** each fact beside its cited lines; text output escapes control and
  direction-changing characters, JSON keeps the fields unchanged.
- **`skills/spec-format/scripts/drift.py`, `spec.py drift <rev> [--pin NAME] [--rewrite]`:**
  moves one entry's pin to a full new commit; rewrites moved line ranges in place and inserts
  `stale: {was: <commit>}` for anchors whose text changed. It validates the original, rewrites a
  single snapshot of the bytes, verifies the result (D9), stages an exclusive temporary file
  beside the original and replaces atomically. Only the selected entry's anchors are judged.
- **Checker hook** (`speccheck.py`): a `stale` anchor fails `check` as well as `resolve`.
- **Tests:** `test_resolve.py`, `test_drift.py`, `test_review_r1.py`, `test_review_r2.py`,
  `test_review_r3.py`, `test_review_guard_coverage.py`, `test_replace_policy.py`, with local git
  fixtures. The spec-format suite holds 385 tests, one gated skip.
- **Docs:** the design's D9 and D12 text, `SKILL.md`, and the glossary's Data path row.

Consequential findings and their resolution:

- **Drift wrote the wrong span** (rounds 2 and 3, Codex). First a stale index applied to a reread
  file, then an indentation taken from a layout the splicer did not model. Patching the splicer a
  second time was the stop rule's cue. Resolution: the rewrite is no longer trusted. Drift loads
  its own output strictly and compares keys, values and types against a deep copy of the original
  with only the intended pin, moved lines and stale markers; the first differing data path is
  reported and the original bytes stay. The Opus reviewer drove 27 layouts and 26 injected
  corruptions through the gate: each was verified with the intended data or refused, none
  accepted wrong data.
- **File replacement changes what the user has** (rounds 2 and 3). Writing in place could
  truncate a spec; atomic replacement turned a symlink into a regular file and broke hard links.
  Resolution: stage an exclusive temporary file with the original mode, and refuse symbolic links,
  hard-linked, read-only, setuid and setgid targets before source access and again before
  staging.
- **File policy not rechecked after staging** (confirmation, Codex). A link, mode or symlink
  change made while the staging file was written still reached `os.replace`. Resolution:
  `replace_snapshot` reruns `rewrite_file_check` before the final byte comparison (`74dac1b`).
- **A pin must mean its commit.** Local object replacements (`git replace`) and worktree edits
  could change what a pin read. Resolution: replacement refs are ignored and a local checkout is
  read at the declared commit only.
- **Operational failures are not content changes.** A failed blob read marked anchors stale.
  Resolution: only missing or changed content stales an anchor; any operational error retains the
  original.

**Orchestrator, accepted before review:** `drift` takes only a full new commit and one entry
(`--pin`); `--docs-dir` names documents by their resource name; device-tree anchors read
decompiled or source text and refuse binary blobs; a search anchor checks scope existence only
and cannot be marked stale (the schema forbids it); a fully skipped run exits 0, as format 1's
fetch does; the 200-line preceding symbol window is kept but a miss is an error.

**Orchestrator, review rulings:** round 1 separated content failures from operational ones and
folded the SPDX rule into D12; round 2 simplified the SPDX rule to the kernel's (first tag in the
first five lines), made drift snapshot-based and checked source-independent anchor errors before
any source access; round 3 accepted the residual cases below.

## Limitations and follow-ups

- **Accepted residual:** an edit landing between the final byte comparison and `os.replace` is
  lost. Both Claude and Codex reviewers observed this window in earlier versions; it is inherent
  to compare-then-replace without a lock.
- **Explicit-key layouts are always refused.** The splicer still computes a wrong indentation
  for a mapping written with `? key`; the verify gate catches it, so valid specs in that layout
  can never be rewritten by drift. (Opus nit 1.) A line in the docs or a test pinning the
  refusal message is the follow-up.
- **`--rewrite` on a directory exits 1, not 2.** The file-policy pre-check has no regular-file
  test, so the message reads "more than one hard link". Without `--rewrite` the same input exits 2
  with "expected a spec file". Extended attributes are also dropped by replacement. (Opus nit 3.)
- **Dead code at `drift.py` line 94.** `comments.extend(... source[end:])` never changes the
  result, because the final token already starts at the end of the text (mutant P12, equivalent).
  (Opus nit 4.)
- **Misleading summary after a rewrite.** The text output ends with "0 anchor(s) resolved, 0
  skipped" even after a successful rewrite, because it reuses `resolve`'s summary. (Opus nit 4.)
- **Comment association on insertion.** A `stale` line lands after comment lines that follow the
  anchor. Data and comment bytes are equal, which D9 accepts. (Opus nit 2.)
- **Transfer limits bound retained bytes,** not bytes in flight. **Searches establish scope
  existence,** not the truth of prose.
- **Out of scope here:** `inventory` and peripheral specs (SF2-7), the contract and skills
  (SF2-8), the CI workflows that call `resolve` (SF2-11).
