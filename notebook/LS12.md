# LS12: consumers updated

Milestone of the [license-split plan](../docs/LICENSE-SPLIT-PLAN.md#ls12--consumers-updated).

### 2026-10-07 — opening

Goal: LS-R19 and LS-R13. Three consumers (`fuchsia-skills`, `bringup-kit`, `public-skills`) and
this repository's marketplace entry, each on `license-split/ls12` from a fetched `origin/main`.
Start with a grep of each consumer for the old names to see the size of the job.

### 2026-10-07 — decision: `rpi-expert` has no successor

The per-board experts were removed from driver-lab by the commit "Remove the published board
specs and per-board expert stubs"; `board-expert` now reads specs, and none ship. So the
`fuchsia-source` and `fuchsia-driver-bind-debug` references to `rpi-expert` could not be renamed.
They now point at `hardware-investigator` and `board-expert` (and `cleanroom-investigator` for the
clean-room case), which exist; the README and onboarding text says plainly that no per-board expert
ships today.

### 2026-10-07 — decision: historical records in `bringup-kit` keep their names

`bringup-kit` holds about 70 captured question-and-answer sessions, prompt analyses, a routing
eval's results and two dated documents that quote the old skill names. They are records of what a
session said, not instructions, and rewriting them would falsify them. `laps/` was already out of
scope; `AGENTS.md` now declares the rest as historical paths so the grep has a stated exclusion
rather than a silent one.

### 2026-10-07 — dead end: a negative mention fails its own grep

My first drafts of the declaration in `bringup-kit`'s `AGENTS.md` and of its README spec-roots
paragraph named the stale skills and `hardware-specs-gpl` in order to say "do not use them".
That is the exact string the acceptance grep looks for. Reworded to describe them
("the GPL-licensed spec repository") instead of naming them.

### 2026-10-07 — dead end: `check-open-side` and the marketplace sentence

I added a sentence about the clean-room skills to this repository's marketplace description;
`check-open-side.py` refused it ("clean-room" outside the allowlist). The pointer to
`cleanroom-skills` stays in the README line the check allows; the marketplace entry just lists the
current skills.

### 2026-10-07 — bringup-kit's scrub test fails before and after

`test_scrub_is_clean_on_the_kit` fails on the working checkout, with 37 hits, before my change
(stashed and rerun) and after. The hits are in other sessions' worktrees under `.claude/` and an
untracked handoff file, not in tracked files. The evidence shows the suite run from a clean export
of the commit instead.
