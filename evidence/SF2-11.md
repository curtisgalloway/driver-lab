# SF2-11: the three spec repositories cut over and published

**Terms:**

- *root*: the marker file that declares a spec repository's license policy.
- *context repository*: another spec repository whose roots a check or build reads, so a
  reference across licenses can be resolved.
- *upstream-stale*: a fact cites another fact whose text changed after the citing verdict.
  The pull-request mode treats it as an error; the `main` mode as a warning.
- *merged view*: a rendered page that combines a repository's specs with those of its context
  repositories.
- *fit / misfit*: a scratch change the license gate must accept / must refuse.

See the [glossary](../GLOSSARY.md) for the rest.

Consequential findings and their resolution:

- **Deploy job ran on forks (Codex, all three).** A fork has no Pages site, so the job would fail
  on every push there. Resolution: the deploy job is guarded to the owning repository.
- **S1, text that said context errors are warnings (Opus).** The `checks.sh` header (all three)
  and the permissive and gpl README text, carried over from format 1, said a context root's own
  errors only warn downstream. Under format 2 a context root with an error is untrusted and the
  dependent fails. Resolution: the text corrected in the fix round; no code changed.
- **S2, no branch protection on the repositories (Opus).** Nothing stops a merge on red CI, and a
  downstream pull request reads the upstream `main`, so its CI is red until the upstream merges.
  Resolution: a procedure, not a code change: merge only on green, and re-run each downstream
  pull request after the upstream merge. It was followed (below).
- **A TODO that asserted facts across a license boundary (Codex).** The docs `bcm2711` TODO about
  peripheral mode selection stated facts from another repository's sources. Resolution: reworded
  and its fact re-verified in the fix round.
- **Two gpl references that were prose only (Codex).** Resolution: made structured references and
  re-verified.
- **`.gitignore` gap in gpl.** CI checked out the permissive context under a path the repository
  did not ignore. Resolution: added with the fix round's other nits, with the checkout action's
  major version aligned across the workflows.

## Decisions

**Orchestrator, under the user's overnight instruction (2026-10-09):** the work was split. The
night prepared everything without merging (the plan's step 2 says "with the user's go"); the
merges and Pages enablement waited for the user. The fix round took workflow and documentation
fixes and spec fixes that needed re-verification, and no new facts. Context repositories are read
at `main`, as the checks workflow already did, rather than at pinned commits, because a post-merge
commit does not exist before the merge and a pin would need a bump after every upstream merge.

**The user (2026-10-10):** "Go, all three". Approved the merges, Pages enablement and the
scratch push for the upstream-stale proof.

## Limitations and follow-ups

- **Context repositories are read at `main`, not pinned.** A published site can change when an
  upstream repository changes. The build job records each context commit and the deploy job
  checks out the same commits, so one run is consistent with itself, but two runs are not
  comparable without that record.
- **The upstream-stale proof used a scratch branch whose upstream fact was also own-stale in
  docs.** A merged docs `main` would not carry an own-stale fact. The dependent's judgment
  compares the basis hashes in its own verification record, so the review judged the result the
  same; the published run shows exactly one error, the upstream-stale reference.
- **The `main` mode warning was shown by `workflow_dispatch` on a scratch branch,** not by a push
  to `main`: pushing a stale fact to `main` was not done deliberately. The workflow maps push and
  dispatch events to the same mode.
- **No branch protection** on the three repositories (S2). Merge order was kept by hand: each
  downstream pull request's CI was re-run after the upstream merge, and each merged on green.
- **Docs has no merged view,** because it is the first root. This is by design.
- **Format 1 is still in driver-lab.** Removing it is SF2-12; the repositories no longer depend on
  it.
