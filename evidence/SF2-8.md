# SF2-8: the format 2 contract and the board-spec skills

**Terms:**

- *contract*: the written rules for format 2 specs, in `skills/spec-format/SKILL.md`; the JSON
  schemas stay the authority for field shapes.
- *trace review*: a reviewer takes each rule a document states and finds the schema line, code
  line or design line that makes it true; a rule with none is *untraceable*.
- *enforced / design-only*: a traced rule is enforced when a schema or checker rejects its
  violation, design-only when only the design document backs it.
- *format 1 text*: the earlier Markdown contract, kept in `FORMAT-1.md` files until SF2-12.

See the [glossary](../GLOSSARY.md) for the rest.

## What was built

- **Contract (`skills/spec-format/SKILL.md`):** kinds and what goes where, facts, support classes
  and anchors, references in their three forms, roots and the license gate, records, commands and
  rendering. Shapes are cited from the schemas, not restated. HTML rendering is described as
  SF2-5. `skills/board-expert/SPEC-FORMAT.md` is a pointer to both formats.
- **`board-expert`:** reads format 2 (merged Markdown view with status, YAML for exact fields) and
  keeps an explicitly labeled format 1 reading path. The format 1 contract text is retained,
  unchanged, in `skills/board-expert/FORMAT-1.md`.
- **`board-spec-scaffold`:** ten YAML templates (board, soc, chip, ip, overlay, root marker,
  documents-only variants) with placeholders; verification points at `spec-verifier`.
- **`spec-verifier`:** the format 2 procedure (records keyed by fact id, basis hashes, `readers`,
  `contrary_evidence`, `citation_precision`, `carried_from`, delta verification from
  `status --stale`, the second reader, TODO-method check, the `[src]`-about-hardware rule), the
  retained `FORMAT-1.md`, and a synthetic worked example that a test runs verbatim.
- **Other:** `GLOSSARY.md` rows; `skills/campaign-review` now reads the support-class enum from the
  schema instead of the old contract's prose (a dependency the move exposed).

Consequential findings and their resolution:

- **Format 1 contract deleted while still cited (blocker, Opus).** SF2-8a cut the 780-line
  `board-expert/SPEC-FORMAT.md` to a pointer, but `peripheral-spec` (three places), two script
  docstrings and SF2-8b's `FORMAT-1.md` cite its sections, and format 1 stays live until
  SF2-9 and SF2-12. Resolution: the original text moved, byte-identical, to
  `board-expert/FORMAT-1.md` (labeled format 1, retained until SF2-12), and the citing files were
  repointed.
- **Device-tree blobs.** The contract said blobs need a node, but the schema accepts lines alone
  and the resolver reads pinned bytes as UTF-8, so a binary `.dtb` cannot resolve. Orchestrator
  decision in the fix brief: DT claims cite source text (`.dts`/`.dtsi`) at a pin; a claim whose
  only source is a binary blob is a gap until decompiled text is published at a pin.
- **Confidential documents.** Nothing stopped an author citing a widely circulated document marked
  confidential (the RK3588 TRM) in a public root. Orchestrator decision: public roots never cite
  documents marked confidential or under NDA, whatever their availability; use a public proxy, a
  GPL overlay with DT or source, or a gap. Added to the contract and the scaffold.
- **Probe stumbles.** Authors guessed the interrupt-ID arithmetic wrong, did not know each SoC
  instance needs a resolving `ip` spec (`instances: []` is the minimal form), and could not
  refer to the target's facts from an overlay. All three are now stated in the contract and
  templates.
- **Worked example teaches a bad pattern (SF2-8b).** Its inference was settled by the cited manual
  itself and the GAP verdict's required fields were unexplained. The example now derives a total
  from two separately cited phases, and the GAP row documents its fields.
- **Verifier gaps (Codex, SF2-8b).** Only previous PASS verdicts may be renewed from an upstream
  change alone; readers must inspect notice and license-file evidence; peripheral and review
  support is marked as arriving with SF2-7.
- **Duplicate glossary rows** from the two halves were reduced to one set.
- **Templates silently shipped Apache headers** into a CC-BY docs root. All templates now take the
  SPDX header as a placeholder and the test checks it against the root's license.

## Decisions

**Orchestrator, in the fix briefs:** DT claims cite source text at a pin and a blob-only claim is
a gap; public roots never cite confidential or NDA documents; SF2-8a keeps the shared glossary
rows and SF2-8b drops its duplicates. No stop rule fired and no user decision was needed.

## Limitations and follow-ups

- **Untraceable rules (6 of 176).** Four have no schema, code or design line and were not
  contradicted: "trace executed control flow" for `[src]` claims, "machine paths never go into
  specs" (the privacy check covers repository files, not spec roots elsewhere), board-expert's
  trigger matching with longest `not_triggers` first (carried from the format 1 reader), and
  board-expert's rule against `drift --rewrite` without an authoring request. The other two were
  contradicted and fixed in this milestone.
- **Design-only rules (22)** are backed by the design document but not rejected by any checker.
- **Reviewer nits not fixed:** the contract's `drift` synopsis reads `<commit> <file>` while the
  command takes `revision files [files ...]`, and the `--skill` render synopsis omits
  `--require-license` and `--public-skill`; command blocks say `python3` although the
  dependencies live in the hash-pinned virtual environment; the format-choice sentence differs
  between the contract ("without `format` or `format: 1`") and the verifier ("a root without
  that field"); the glossary's viewer row still says Markdown rendering "arrives in SF2-4"
  though it has landed; the worked example's critical fact is not one of the kinds the contract
  prescribes (it is marked critical only to demonstrate `readers`).
- **Not enforced by tooling:** a DT anchor on a binary path with only `lines` passes `check`; the
  text now tells authors not to cite blobs rather than the schema refusing them.
- **Out of scope here:** HTML rendering (SF2-5), peripheral, review and investigator skills
  (SF2-9), format 2 peripheral specs and reviews (SF2-7), retiring the format 1 readers and
  checkers (SF2-12).
