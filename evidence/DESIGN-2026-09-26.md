## The user's direction (2026-09-26)

- The goal: "to generate a system to create reliable specs and test them, and over time ensure
  that we continuously review and correct them as the evidence changes and models get better.
  Having good fixtures is important but there are diminishing returns to getting every possible
  last thing corrected."
- The organizing axis: three sources of change, "bugs and things identified while actually
  writing drivers and testing against real hardware; updated documents and reference software;
  and improved AI tools and models that might generate a better result with the same
  information", with new tools and data sources in the second. This became the design's
  three-source table.
- Private use: the "updated sources" category will be exercised elsewhere with confidential
  material, so the method must deploy in a separate environment with nothing flowing back (C7).
- Extension points for tools that cannot be public, kept minimal and following the existing
  plugin and packaging conventions (C8).
