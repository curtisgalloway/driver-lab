# LS11: firewall by name

Milestone of the [license-split plan](../docs/LICENSE-SPLIT-PLAN.md#ls11--firewall-by-name).

### 2026-10-07 — opening

Goal: LS-R18. Code in `cleanroom-skills` (starting `9db0dc6`), records here (starting
`40953c8`). Plan: tests first, shown failing, then the hook.

### 2026-10-07 — decision: the names are code, not policy

The policy file is per workspace and the implementer works there. If the four names lived only in
the default policy, a workspace policy that predated them (or left them out) would quietly turn
the firewall off. They are a constant in the script; the policy can add names, not remove them.

### 2026-10-07 — decision: match by name, then resolve what the filesystem shows

A substring on the name covers every install path, case and `..` at once, and covers the `Skill`
tool and subagent prompts if applied to every argument key, not only path keys. The cases that
never write the name (symlink, glob, `cd` then a relative read, `$VAR`, a recursive search above
the directory) need the filesystem, so the hook resolves them when it is given a working
directory. The audit passes none, since a recorded session came from another machine.

### 2026-10-07 — dead end: a test that cannot fail

Two glob tests used `wide/*/x` and `wide/b*/x`; a glob only matches paths that exist, and there
was no `x` file, so nothing matched on the first code or the fixed one. Caught by the fail-first
run on a copy with the fix reverted, which showed them failing for the wrong reason only after
the files were examined. Rewritten to glob the directories themselves.

### 2026-10-07 — dead end: stash with an intent-to-add file

Reverting the fixes with `git stash push <file>` failed because the untracked fixture had been
marked intent-to-add for the diff the swarm reads. Nothing was stashed. The pre-fix run used a
scratch copy of the scripts with the fixes reverted by hand instead.

### 2026-10-07 — review and checkpoint

`review-swarm`: seven arms and a referee, 15 findings verified, 11 kept; three medium findings
were real bypasses (assignments after `export`, a `#` comment in the shell words, a glob cap that
could skip the blocked entry). Fixed with tests that failed first; the decisions and the rest are
in the [evidence](../evidence/LS11.md). Checkpoint commits follow.

### 2026-10-07 — commit security review

An automated review of the checkpoint flagged fail-open caps and form-parity gaps (by summary
line). Fixed in a second `cleanroom-skills` commit: every cap but scan depth now denies with a
"narrower path" message; Grep and Glob with only a pattern scan the working directory; an
unknown argument that is a symlink is resolved. Decision: keep the substring match rather than
switch to component matching, since a component match lets a suffixed copy through. The records
commit was amended (nothing pinned it).

### 2026-10-07 — second review-swarm on 35ff17e

The fail-closed commit had only its suites behind it, so it got its own swarm: 24 findings
verified, 15 kept. The real ones were `git` reading content without a scan, a brace expansion that
quietly gave up after three rounds (the cap that was supposed to fail closed), and search
patterns expanded as paths. Fixed in one `cleanroom-skills` commit. Dead end: the first draft of
a test ran `main()` in-process without a project directory and wrote a log into the repository;
folded into the existing `run_main` case instead. Another: `git blame src/main.rs` is
rightly allowed (it names a clean file), so the test used `git whatchanged`. The query-key and
`| grep` scans were left as recorded false denials, since narrowing them reopens a bypass.
