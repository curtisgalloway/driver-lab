# SF2-12: format 1 retired

**Terms:**

- *format 1*: the earlier Markdown spec format (`*.spec.md` files with tagged claims) that
  `spec_check.py` and its siblings read.
- *format 2*: the YAML spec format that `spec.py` reads and checks.
- *root marker*: the file that declares a spec root's format and license policy.
- *frozen archive*: the `evals/` tree, its plans and the documents that describe them, kept as
  history and still checked by CI.
- *preflight*: the license check `hardware-investigator` runs on a root's marker before it reads
  any source evidence.

See the [glossary](../GLOSSARY.md) for the rest.

## What was removed, and what replaced each live use

| Removed | Replacement or resolution |
| --- | --- |
| `spec_check.py` (board Markdown checker) | `spec.py check`; the investigator's preflight now shares format 2 marker validation and the SPDX policy |
| `anchor_check.py`, `mdtokens.py` | Nothing imported them from format 2; structured checking and resolution replace Markdown parsing |
| `inventory_check.py` | the typed `spec.py inventory` |
| `fetch_src_pins.py` | the format 2 resolver's fetch implementation (its docstring was stale and is corrected) |
| `migrate.py` | removed from the CLI and the current documentation; `spec.py migrate` is now a usage error |
| five `FORMAT-1.md` files | the format 2 contract in `spec-format`; skills point there |
| v1 board and peripheral fixtures, and their tests | format 2 fixtures and tests already cover the retained behavior; the negative fixtures that reject format 1 stay |
| the campaign stand-in's call to the old board checker | its generated spec and handoff are now format 2, with the same four invented claims |

The shipped `board-expert` root held only its marker, so no spec needed converting; the marker
now declares `format: 2`. `peripheral-spec`'s test directory and its CI step went with the
scripts. `markdown-it-py` stays pinned as the CommonMark library (D20). Skill names, the frozen
archive, carried-verdict provenance and the pinned requirements are unchanged. CI and the
`AGENTS.md` list run the format 2 checks, and the archive checks that used an unpinned install
now run in the hash-pinned `.venv-sf2`.

## Decisions

**Orchestrator:** Codex implemented the unit, following the SF2-9 precedent. The orchestrator
applied the CI workflow and `AGENTS.md` list edits itself, taking Codex's proposals, because
those files are patch-gate inputs the implementer must not change. The archive checks that ran in
an unpinned install now run in the hash-pinned `.venv-sf2`, so one environment serves them all.

## Limitations and follow-ups

- **`bringup-kit` reads its YAML records with a small reader of its own,** because the kit takes
  no dependencies; it handles the record fields replay needs (`format`, `spec`, `spec_file`, the
  summary counts), not general YAML.
- **The reviewer ran `license_gate.py` under the pinned environment only.** It now needs the
  hash-pinned dependencies and exits 3 without them, by design.
- **`license_gate` does not refuse a symlinked root in the preflight** (the `--facts` path does).
  This behavior predates the change.
- **The default Git-based privacy and open-side scanners** were run in the worktree after the
  files were staged intent-to-add; the implementer's own run, in an export without Git, used
  the same scanners over an enumerated file list.
