# SF2-1: strict loader, pinned dependencies, core schemas

**Terms:** *format 2* is the YAML spec format of the [design](../docs/SPEC-FORMAT-V2.md); a
*schema* is a JSON Schema (draft 2020-12) stating what shape a file must have; the *loader* is
`load_strict`, the one function that reads YAML for every format 2 tool; a *fragment* is the
partial schema an extension supplies for its support class (D15); a *mutation check* removes one
guard to confirm that a test notices (all in the [glossary](../GLOSSARY.md)).

[SF2-1](../docs/SPEC-FORMAT-V2-PLAN.md#sf2-1--strict-loader-pinned-dependencies-core-schemas).

(ledger, dep-quality output, mutation logs, check logs, the six review artifacts).

## Reviews

Code-unit method (plan conventions): an executing Claude reviewer and a Codex `ro` diff review per
round. Artifacts, by run-store-relative name in run `sf2-1-20261008-01`:

| Round | Codex | Claude | Outcome |
| --- | --- | --- | --- |
| 1 | `review/codex` | `review/claude` | one blocker (Python `$` matches before a final newline), eleven should-fix; all fixed (`0c8e09f`, `57252f7`) |
| 2 | `review/codex2` | `review/claude2` | no blockers; seven should-fix and nits; fixed (`332440c`), exit code revised (`ba85377`) |
| 3 | `review/codex3` | `review/claude3` | no blockers; three should-fix and two nits, fixed with tests (`8a64503`); no fourth round (stop rule) |

Consequential findings and their resolution:

- **Trailing newlines passed every pattern** (round 1, blocker): patterns end with `(?![\s\S])`,
  never `$`; tested per pattern family.
- **A lone CR or NEL was rewritten by PyYAML before any value was seen**: the loader scans the
  whole file first; invisible characters in comments are refused too.
- **Free-text fields that later reach a command line** (`ref`, `symbol`, `node`): a git ref-name
  pattern, no leading `-`; SF2-6 passes them only as arguments after `--`.
- **Extension fragments could escape the core's rules** (`$ref` under a field named `properties`,
  legacy `dependencies`, `$` anchors, names with newlines): a schema-aware walker, draft 2020-12
  keywords only, whole-string names, no `$`, `\Z` or `(?#`, a character scan.
- **The unknown-key filter hid or invented findings**: it now drops only keys declared by the
  branch that applies (kind and class `if`, satisfied `anyOf`/`oneOf` branches); closed records
  (`additionalProperties`) are never filtered.

Round-3 dispositions: fragment regex comments and `\Z` refused (`[]$]` accepted); unknown keys
under alternatives reported; uppercase 40/64-hex refs refused; an exception in the dependency
check is exit 100 with the JSON object; tests added for `fetch_via` with `<` and `>`.

## Decisions made by the orchestrator (2026-10-08)

Within the design's scope; recorded in the plan's Decisions and, where the format changed, the
design text.

1. **Locators:** a `databook` locator is always precise; a `standard` one only when its document
   entry has `pages` (checked in SF2-2). The design's Locators paragraph is amended.
2. **No empty optional lists:** absent or non-empty; required lists that may hold nothing keep
   `[]`. The worked example lost `aliases: []` and `readers: []`.
3. **`symbol` widened** to C++ and assembler spellings (single-line, no leading `-`).
4. **`accepts` required** in a root marker; `[]` means documents only.
5. **`resources`** absent or non-empty (`minProperties: 1`).
6. **`fetch_via` and retrieval `via`** are prose, never executed.
7. **Requirements markers:** only `python_version` / `python_full_version` comparisons, padded to
   three parts; anything else is exit 3.
8. **Internal errors exit 100**, the tool-specific band; exit 4 was chosen first and reversed,
   since the house exit-code contract reserves 4 for "target unreachable".

The user (2026-10-08) approved GitHub Pages for SF2-11 and kept the implementer and reviewer
models; both are in the plan.
