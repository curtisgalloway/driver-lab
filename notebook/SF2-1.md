### 2026-10-08T12:41-07:00 — decision: loader details the table leaves open

An empty plain value (`key:`) is an error, not null and not `""` (a second spelling of both);
`-0` stays a string, not a second zero. Refused characters: every control character except
newline (tab included, as the table says), every format character (`Cf`: zero-width, bidi,
soft hyphen, BOM), line and paragraph separators, private-use and unassigned code points, and
every space but U+0020 (a no-break space is a look-alike). The six bcm2711 v1 files hold none
of these and are NFC, so the rule costs the migration nothing. Directives (`%YAML`, `%TAG`) are
errors; `---` and `...` around the one document are layout. Errors name the character's own
line and column when it appears literally, the scalar's start when it was escaped.

### 2026-10-08T12:41-07:00 — decision: schema choices the design leaves open

One spelling each: hex values lowercase with no separators (`0x7e201000`); `critical` only as
`true`, `cite` only as `false`, anchor `comment` only as `true` (omit the key otherwise);
fact-level lists are non-empty and without repeated entries; https for every URL (press,
documents and retrieval too, not only repos), with no user information in the host.
Instances keep v1's shape with `reg`, `irq` and `clocks` required, `null` when unknown, and a
`todo` then required. Kinds `peripheral` and `review`, and the fact fields `data` and
`requirement`, are refused until SF2-7 defines them. The D15 hook is a marker field
`extensions: [{class: source-observed, schema: <json file inside the root>}]`; the fragment
may only declare `type: object`, `properties` and `required` (no `$ref`, no keyword that would
mark every key evaluated), and `validate --root <dir>` loads it; without it a
`source-observed` entry is refused. The file name picks the schema, and `kind: facts` lives
only in `*.facts.yaml`. Every `spec.py` subcommand requires all three direct pins at their
versions (exit 3 otherwise).

### 2026-10-08T12:41-07:00 — attempt: closed records under conditionals, and their noise

`unevaluatedProperties: false` with per-kind and per-class `if`/`then` closes every record,
but a failing value inside a branch drops the branch's annotations, so every key the branch
declared also reads as unknown (`id`, `anchors`). `spec.py` now reports such a key only when
no schema declares it or nothing else failed at or below its object. Two more traps found by
the tests: `required` inside `if` or `not` is vacuously true on `null` (the nullable `irq`
needed `type: object` in its `if`), and an all-digit commit loads as an integer (D6 working as
designed), so a type error on a non-string now says "quote it".

### 2026-10-08T13:22-07:00 — attempt: the fixes, each with a test that fails on the old code

Loader (`0c8e09f`): the whole file is scanned before PyYAML rewrites line breaks (a lone CR or a

### 2026-10-08T13:22-07:00 — surprise: `re.sub` ate the backslashes of a JSON regex

Re-anchoring the schema's patterns with `re.sub(..., END + '"', s)` turned `\\s` into `\s`
inside the JSON text, because a replacement string's backslashes are processed; the script's
assertions stopped it before it wrote. A function replacement (`lambda m: ...`) keeps the text
literal. The same rewrite also had to catch interior anchors (`(/|$)`), not only final ones.
