# L02d2 — QEMU harness, second half: scenarios and planted defects

Goal: the rest of the design's §5 scenarios on the L02d1 harness, a kernel-log check in every
scenario, the ITR read-back decision, probes for L02e's open items, per-phase trace grouping
for L02f, and planted defects that the suite must detect
([plan](../IMPLEMENTATION-PLAN.md), L02d and L02d2). Verdict record:
[evidence/L02d2.md](../evidence/L02d2.md).
Terms: the DUT (device under test) is the guest driving the emulated e1000; the peer is the
second guest; a planted defect (mutation) is a deliberate bug in a disposable copy of the
reference driver. See the [glossary](../GLOSSARY.md).

## 2026-09-24T17:51-07:00 — decision: ITR read back through the memory BAR (L02b C-2)
The `itr` scenario reads ITR with busybox `devmem` at the BAR address sysfs gives, and a
deferred check compares that read (it appears in the trace too) with the last ITR write
before it, or with 0 after a global reset. This tests the device model and the driver's
write together without assuming any particular value; spec revision 4 allows ITR = 0. The
reference reads back 0xc3 (195, about 20,000 interrupts/s) and writes five distinct values
over a run (195, 205, 279, 434, 976).

## 2026-09-24T17:51-07:00 — surprise: QEMU's e1000 does not overrun, it pushes back
r002: with the DUT's interrupts masked, the model logged no `e1000_receiver_overrun`, and
the peer's ping stopped with "No buffer space available". When the ring is full the model
stops accepting frames; the backlog reaches the peer. So there is no MPC/RNBC count and no
RXO cause to observe in emulation. The check now reads RDH and RDT while masked: r003 read
RDH 5, RDT 5 (the head reached the tail, SDM 3.2.6), and reception resumed after the mask was
restored. The overrun event count stays as an observation for L02f. A model limitation for
the `[emulated]` class.

## 2026-09-24T17:51-07:00 — surprise: the packet captures' clock is about 8 h off

## 2026-09-24T18:07-07:00 — attempt: four planted defects, first round

## 2026-09-24T18:07-07:00 — surprise: a failing driver made the harness declare the DUT dead

but the harness marked it dead and every later scenario FAILed on that, so later scenarios
told nothing about the defect. Now `ping -A ... -w 60` and `wget -T 20`. Round 2 gave every
scenario its own verdict.

## 2026-09-24T18:07-07:00 — decision: m1 is not a defect under the manual; m5 replaces it
The design's first example, "receive tail written one descriptor early", hands the device
one fewer buffer. SDM 3.2.6 lets software give the device any number of descriptors, and the
reference already holds one back (it writes the tail as next-to-use minus one). No manual-based
check can fail on it, and none should. It stays in the record as an equivalent mutation. m5
plants the defect the example was reaching for: the receive tail is written only on the first
fill after load, so the ring runs dry after about 254 frames and a reopen never gives the
device any buffers.

## 2026-09-24T20:37-07:00 — correction: the ITR decision entry (17:51) overclaimed
The 17:51 entry says the read-back "tests the device model and the driver's write
together". It does not: it compares the model's stored value with the model's own log of
writes, so a driver that never writes ITR, or writes a wrong value, passes. It is a model
and decoder consistency check; the driver's writes after its last reset are now recorded
as an observation for L02f. Found by the coverage reviewer (C4).

## 2026-09-24T20:37-07:00 — surprise: link-loss-tx never held transmits through the outage
The coverage reviewer measured 1,403 TDT writes in the first 1.6 s after the link dropped
and none after: QEMU's model keeps completing transmit descriptors with the link down.
L02e item L4 cannot be reproduced in emulation; the scenario now checks that carrier fell
and says so. Likewise M2: no ring landed above 4 GiB with the reference, so the DMA-mask
probe did not happen for it.
