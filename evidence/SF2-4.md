# SF2-4: CommonMark checks and the Markdown view

**Terms:**

- *CommonMark*: the standard Markdown grammar. The checker parses author text with one pinned
  CommonMark library (markdown-it-py 4.2.0).
- *GFM* (GitHub Flavored Markdown): GitHub's superset of CommonMark. It adds tables, strike-through,
  task items, footnotes and automatic links, so text that is inert under CommonMark can be active
  under GFM. The reference GFM renderer used in the reviews is cmark-gfm.
- *fence*: a run of three or more backticks (or tildes) on its own line that opens and closes a
  block of literal text.
- *code span*: text between two equal-length runs of backticks inside a line, shown literally.
- *Markdown view*: the generated reading copy of a spec (`spec.py render --format md`). Nothing
  parses it for meaning.
- *container*: the fence or code span around one piece of author text in the view.
- *stop rule*: two review rounds finding the same kind of defect means the design is wrong and the
  user decides, instead of a third patch.
- *mutation check*: removes one guard to confirm a test notices.

*Mutation check* is also in the [glossary](../GLOSSARY.md); the other terms are defined above.

## What was built

- **`skills/spec-format/scripts/textcheck.py`, `specmd.py`:** the shared CommonMark module. It
  reports only findings (raw HTML block or inline, disallowed link or autolink scheme, heading,
  unclosed fence, link reference definition, footnote, nesting deeper than 16, delimiter runs over
  32) and returns no provenance information. The v1-tag lint is a warning.
- **`skills/spec-format/scripts/render_md.py`, `spec.py render --format md`:** banner, identity
  block, resources tables, context section, one block per fact with the generated provenance
  block and full reference, overlay sub-headings, `--with-status`, merged views. Author text goes
  in fences with no info string and a delimiter longer than any content run; generated syntax
  goes in code spans. The rendered view is checked again against the places the generator put
  fences and headings before it is written.
- **Source identity:** explicit `--source-commit ROOT=SHA` per root; a root without one reads
  "unavailable". No Git lookup remains. The SHA-256 covers the bytes the loader checked.
- **Diagnostics:** forbidden or control-character file names are visibly encoded in text output.
- **Tests:** `test_textcheck.py`, `test_render_md.py`, `test_sf2_4_r1.py` to `test_sf2_4_r4.py`,
  `fixtures/textcheck/cases.json` and the mutation runner `mutate_sf2_4.py`. The spec-format suite
  holds 316 tests.
- **Docs:** the design's Rendering and Validation text, including the stated limit that the
  assembled check is CommonMark-only and the view's GFM safety rests on the fences and code spans.

Consequential findings and their resolution:

- **Author text escaping its container** (rounds 1 and 2). First across a field boundary through a
  reference definition, then within and across fields under GFM through fences and tables.
  Resolution at the stop rule: the view no longer tries to make author text safe by checking it.
  Every author field (claims, notes, orientation, milestones, notices, stated premises) is a
  labeled top-level fence with no info string, and generated syntax and autolink candidates are code
  spans. The assembled check compares explicit heading and fence placements and exact fence
  contents, and allows only generated constructs elsewhere. The confirmation audit found 0 escapes.
- **GFM length limits** (confirmation, Codex). cmark-gfm stops recognizing fences at 255 backticks
  and code spans at 80, so a delimiter chosen "longer than the content" can become inactive.
  Resolution: backtick runs over 32 are refused everywhere in decoded strings, keys and displayed
  paths, with assertions that no emitted delimiter exceeds 33; notices keep their Markdown exemption
  but share the bound.
- **The checker's parser goes blind at its own limit** (rounds 2 and 4). First 20 levels, then 64:
  link-label lookahead exhausts the limit silently and leaves no deep tokens, so
  `"![" * 65 + ...` reported nothing. Resolution (`dec6016`): limit exhaustion is tracked in the
  parse environment, including `skipToken` lookahead, and reported as a nesting error; check and
  render exit 1 at depths 65 and 130 in claims and notes.
- **Footnote labels** (confirmation S2). A regex over text tokens missed `[^*n*]`; the plain
  substring `[^` is now refused anywhere in author text.
- **Assembled check is CommonMark-only** (confirmation S3). Recorded in
  `docs/SPEC-FORMAT-V2.md` rather than fixed: the GFM guarantee rests on the fences, code spans and
  the 32-backtick bound, and the Rendering text now says so.

## Limitations (tracked)

- **GFM safety of the view rests on its construction,** not on the checker. The assembled check
  parses as CommonMark; autolinks, strike-through, task items and tables in generated lines are
  prevented by `escape()` and code spans (19,937 fuzzed values, 0 failures).
- **The HTML viewer (SF2-5) must parse with the same CommonMark preset and nesting limit.** A
  viewer that enables markdown-it's `table` rule would split a code span the checker saw whole.
  Record the preset as a requirement for SF2-5.
- **Nesting limit counts token levels, not constructs.** Eight nested list levels or sixteen
  quotes are refused though the documented limit reads "deeper than 16" (Claude nit 1).
- **An inline nesting-limit finding always reports field line 1,** because markdown-it's inline
  state carries no line number. For `"first\n\nsecond\n\n" + "[" * 65 + ...` it reports line 1,
  not 5. Not fixed (`review/codex5` nit).
- **Two `check_view` conditions have no test** (fence inside a list item, fence with an info
  string); the builder never emits either today (Claude nit 2).
- **`--source-commit gpl/../docs=SHA` is refused** because paths are compared as spelled; this
  fails closed (Claude nit 4).
- **Three `test_check` cases fail at long checkout paths** because messages are truncated. The
  failures are about path length, not behavior, and are in the orchestrator's backlog.
- **Out of scope here:** the HTML viewer and publishing (SF2-5), peripheral generated sections
  (SF2-7), image-to-link rendering (SF2-5).
