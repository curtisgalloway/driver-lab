# SF2-2: checker — composition, references and the license gate

**Terms:**

- *root*: a directory of specs with a `board-specs.yaml` marker.
- *context root*: a root read only so that references resolve; its own findings print as
  warnings.
- *reference*: `#id`, `spec#id` or `spec@root#id` (D1).
- *license gate*: refuses a citation of a source whose license the root's `accepts` list does not
  include (D13).
- *untrusted root*: a root whose own check found an error; no reference may rest on it.
- *mutation check*: removes one guard to confirm a test notices.

All of these are in the [glossary](../GLOSSARY.md).

## What was built

- **`spec.py check <root>... [--context-root D]... [--require-license] [--public-skill N]...
  [--stub F]... [--stubs-from D]... [--json]`** (`scripts/speccheck.py`). It validates every
  `*.spec.yaml` below each root against the schema, then checks what a schema cannot:
  - **Roots:** marker `license` and `accepts` parse, in canonical spelling and without repeats;
    root names are distinct; no symbolic links; no nested marker; no file named like a spec that
    discovery passes over.
  - **Composition:** spec ids and aliases are unique; `parts`, `variant_of`, `instances[].ip` and
    overlay targets resolve to the right kind; `parts` has no cycles; an overlay keeps its
    target's layer order and sections.
  - **Names:** `doc`, `repo` and `assumption` resolve in the citing file. A citation's class
    matches its document's, and a `cite: false` document is never cited. Page numbers lie within
    the document's `pages`, without leading zeros, and page ranges run in order; a `standard`
    locator is precise when its document is paged. `lines` run in order. A cited repos entry
    carries a `commit` and lists the cited path in its `files` (D12). `irq.intid` agrees with
    `number`.
  - **Ids:** unique per spec id per root.
  - **References:** the three forms resolve, with layer order respected, no premise cycles, and
    no repeated premise.
  - **The license gate:** one function over board-expert's `spdx.py`, applied directly to
    anchors and notices, and transitively to each reference's reach.
  - **Also:** public-layer privacy; template placeholders; stubs.
- **`scripts/specmd.py`:** the one CommonMark parse (markdown-it-py), used here only to find
  template placeholders outside code; SF2-4 adds the D20–D22 checks to it.
- **The marker's `license` is now required** (root schema and design text). Extension fragments
  are restricted to plain keywords and may not declare citation field names (`spec.py`).
- **Fixtures:**
  - `license-gate/`: the format 1 matrix in format 2;
  - `references/`: seven reference cases, the fail-closed chain, and 19 untrusted-root inputs
    from the reviews plus a healthy root;
  - `check/`: board-expert's good, bad, load-failure and vendor roots and its stubs, in format 2;
  - markers for the worked example.
- **Tests:** `test_check.py` (73 tests), plus new cases in `test_schema.py` and `test_cli.py`. The
  suite holds 167 tests.

## Reviews

Code-unit method: an executing Claude reviewer and a Codex `ro` diff review each round. Artifacts
are in run `sf2-2-20261008-01`.

| Round | Codex | Claude | Outcome |
| --- | --- | --- | --- |
| 1 | `review/codex` | `review/claude` | 3 blockers (the transitive gate failing open on an unresolvable or ambiguous hop; a skipped unlistable directory) and should-fix items. Fixed in `fcd2d45`, `2ba77e8`, `8a2110a` and `2925a94`. |
| 2 | `review/codex2` | `review/claude2` | Round 1 confirmed closed. 5 and 4 blockers of the same kind, met the stop rule. User decision: distrust broken roots, implemented in `7eb4ec3`, `7d55af6` and `6ae225f`. |
| 3 (confirmation) | `review/codex3` | `review/claude3` | Round 2 confirmed closed. Remaining gaps tracked by user decision. |

Consequential findings and their resolution:

- **The transitive gate failed open** (round 1, both reviewers). A docs root could rest on GPL
  source and exit 0 in two ways:
  - a context hop dangled (target root not given, its marker invalid, its spec failing the
    schema);
  - a hop was ambiguous (twin root names, a fact id declared twice).

  Fixed by making the gate fail closed: an unestablished hop is an error on the citing file.
- **Round 2 found more paths of the same kind.** Each was a context-root defect that steered
  resolution while being only a warning:
  - misnamed files (`.spec.yml`, case variants);
  - a schema-failed file with a misleading `id` or `overlays`;
  - a same-name root with an unreadable marker;
  - a duplicate repos name;
  - a fragment admitting `repo` and `path` through `patternProperties`.

  The user's rule closes the class: a root with any error of its own is untrusted, every
  reference resting on it fails (to a fixed point), and while any marker is unreadable every
  root-qualified reference fails.
- **An enumeration failure skipped specs silently:** `os.walk` errors are now errors.
- **A long numeric page crashed the check:** pages are compared as digit strings.

## Decisions

**User (2026-10-08):**

1. **Distrust broken roots:** a reference may only rest on a root that checks clean (the design's
   license-gate section, SKILL.md and the glossary state it).
2. **Merge SF2-2 as is and track the remaining gaps;** no code changes after the confirmation
   round.

**Orchestrator (within the design's scope):**

1. The gate fails closed: what it cannot establish is an error on the checked citing file.
2. `license` is required in a root marker.
3. Placeholders are template-shaped: `<`, a letter, then letters, digits, spaces, `-` or `_`,
   then `>`, outside code.
4. Extension fragments may not declare the citation fields `repo`, `path`, `doc`, `anchors`,
   `lines`, `symbol`, `node` or `url`.
5. Composition (`parts`, `instances[].ip`) stays ungated.
6. Over-blocking is accepted: an unparseable file blocks every qualified reference into its root.
7. The implementer's seven interpretations are accepted:
   - canonical `accepts` spellings;
   - the gate covers conflict anchors, notices, `relates` and observations;
   - one premise per fact;
   - overlay layer order, sections and instances;
   - discovery errors;
   - `series[].target` resolves;
   - `roots:` is not followed.

**History note:** two fixture renames meant for `2ba77e8` landed in `fcd2d45`, so `test_check` at
`fcd2d45` alone fails. The tree is correct from `2ba77e8` on, and the branch is merged as is.

## Limitations (tracked gaps)

Listed with impact and fix point in the plan's backlog. Two of them can let a run pass that
should fail:

- the first, though it needs an extension that uses format 2, and none does yet;
- the second, when a file with an unrecognized name holds a competing candidate.

- **Extension fragments can carry citation-shaped data** inside open nested objects
  (`additionalProperties: true`, `{}`, `items: {}`, object `const`/`enum`, a nested object with
  `required` names). The gate never reads that data. Fix when an extension adopts format 2
  (D15): flat scalars only, or no fragments.
- **Unrecognized file names in a root are skipped with no finding** (`b-spec.yaml`, `b.yaml`,
  `b_spec.yaml`, `b.spec`), so they can hide a candidate while the root stays trusted. Fix: every
  YAML file except the marker, `*.spec.yaml` and `resources/*.verify.yaml` is an error. Watch
  SF2-10's migration output for `-spec.yaml` names.
- **The citing-root exemption:** a same-root reference to an ambiguous candidate gets no error on
  the citing file. The run still fails, on the other file.
- **A rejected symlinked checked root** drops out of name ambiguity. The run still fails with the
  symlink error.
- **Nits:** `reach_roots`' transitive walk is redundant with the fixed point. Untrusted-root
  messages cut the underlying reason at 200 characters.
- **Out of scope here:** records (SF2-3), text checks (SF2-4), anything needing a checkout
  (SF2-6), peripheral and review kinds (SF2-7). The format 1 fixtures stay until SF2-12.
