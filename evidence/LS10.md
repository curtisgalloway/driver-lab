# LS10: `hardware-investigator`

**Terms:** a *target root* is the spec root whose accepts list says which source licenses a
spec published there may cite; a *pin* is a `Source pin:` line (tree, commit, SPDX license); an
*anchor* is a `[src:]` citation resolving against a pin; the *license gate* is the check that
every cited pin's license is on the accepts list (all in the [glossary](../GLOSSARY.md)).

Design: [LICENSE-SPLIT.md](../docs/LICENSE-SPLIT.md) (LS-R17). Plan:
[LS10](../docs/LICENSE-SPLIT-PLAN.md#ls10--hardware-investigator). Notebook:
[LS10](../notebook/LS10.md). Starting revision: `origin/main` `433469f` (LS9 merged).

**Status: complete at the checkpoint;** pushes and the pull request are the orchestrator's.

## What changed

- `skills/hardware-investigator/SKILL.md`: inputs (question, target root, optional sources and
  spec id), a nine-step method, the facts-file format, the *Refused* block and the report. The
  rule is stated first: gate a source's license against the root's accepts list before reading
  it for evidence, not only before citing.
- `WORKED-EXAMPLE.md` with fixtures under `examples/`: two source trees (a Linux-like tree under
  `GPL-2.0-only`, a firmware tree under `MIT`), two target roots (`gpl`, `permissive`), and
  expected facts files. Three runs on `board-expert`'s `widgetuart` fixture.
- `scripts/license_gate.py`: prints a root's accepts list and accepts or refuses SPDX
  expressions using `spdx.py`. Exit 0 accepted, 1 refused (or no accepts list, or an invalid
  marker entry), 2 usage. It was added because hand-evaluating `OR`, `AND` and the `GPL-2.0`
  spellings is the error-prone part; it follows the existing scripts' contract.
- 18 tests in `skills/hardware-investigator/tests` (13 for the script, 5 that run the worked
  example), in `checks.yml` and the AGENTS.md list. README table row and skill entry, two
  glossary rows, the plugin description.
- Plan: LS10 status; LS9's CI box ticked (the orchestrator confirmed all five LS9 pull requests'
  CI succeeded and that they merged on 2026-10-07: driver-lab #53, `cleanroom-skills` #3, #1 in
  each spec repository).

## Limitations

- The method depends on the investigator following step order; the only mechanical backstop is
  the final `anchor_check.py --root`, which cannot tell that a refused source was read.
- `license_gate.py` accepts case variants of identifiers (`mit`) and prints them canonically.
- The worked example's "board-expert" step is the reviewer's reading of the fixture specs; no
  subagent was spawned.
